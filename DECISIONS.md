# Decisions

- 2026-11-15 — Verified (not guessed) why ReCatch appears dead. Five independent hard stops, any one alone is fatal: (1) `AudioCaptureManager.startMeeting()` hard-gates on Screen Recording and returns before the mic ever starts — `CGPreflightScreenCaptureAccess()` is false for the bare binary; (2) the global hotkey and panel wiring are registered inside the MenuBarExtra `.onAppear`, so on a cold start ⌥⌘R does nothing until the menu is opened; (3) default provider is Anthropic but the only stored key is for OpenAI, so the panel answers "No provider configured"; (4) there is no `.app` bundle (no Info.plist, no `NSMicrophoneUsageDescription`, no `LSUIElement`, no bundle id), so TCC identity is per-path and Screen Recording grants do not survive; (5) no overlay and no live captions — the product is a summoned 500pt window. The core pipeline itself is fine: VAD → WhisperKit large-v3-turbo → exact transcript, proven headlessly.
- 2026-11-15 — Added `Sources/ReCatch/SelfTest.swift`: headless probe, `RECATCH_SELFTEST=1 RECATCH_SELFTEST_AUDIO=file.wav .build/debug/ReCatch` runs file → VAD → ASR with no mic and no TCC. Keep it; it is the only fast way to prove the pipeline without clicking.
- 2026-11-15 — Reverse-engineered StreamLingo.app (the inspiration) to settle the hang. It is WhisperKit too: links CoreML, uses `argminc/whisperkit-coreml`, and its own strings are `Base → "smaller and faster"` (default) and `Large V3 Turbo → 627 MB` (opt-in). It also uses Core Audio process taps (`CoreAudioTapSource`, `NSAudioCaptureUsageDescription`) instead of ScreenCaptureKit, mixes mic+system (`SynchronizedAudioMixer`), and does rolling captions (`translationTiming: livePreview`, `usesRollingCaptions`). Translation is Apple's framework, not an LLM.
- 2026-11-15 — Root cause of the 50-minute "hang": we defaulted to `openai_whisper-large-v3_turbo_954MB`; its CoreML encoder compile wedged `ANECompilerService` at 98% CPU and never returned, so `runTranscribeTask` never ran. Matches upstream argmaxinc/argmax-oss-swift#560. Fix: default to Whisper **base** (`openai_whisper-base`), turbo as an opt-in "Accurate" tier, and compute on GPU not ANE (`RECATCH_ANE=1` to opt back in).
- 2026-11-15 — Architecture now mirrors StreamLingo: one `AudioMixer` (mic+system → one stream, labelled by energy), `RollingTranscriber` (7s sliding window, re-transcribe, emit partial captions, commit on 1.2s silence), `SystemAudioTap` (Core Audio tap, falls back to ScreenCaptureKit), `AnswerEngine` (Groq/LLM) only for catch-up answers. Verified live: tap captured system audio, base model transcribed it exactly, overlay window on screen, zero clicks.
- 2026-11-15 — Do not let `flush()` run while a transcription pass is in flight; it finalized with empty text and threw away the result. `flush()` is now async and waits for `busy` to clear.
- 2026-11-15 — Live test against a real meeting video (YouTube: "A Real Daily Standup Meeting Example", played in the browser so the Core Audio tap captured genuine system audio). Verified: tap → Whisper base → 14 segments, no duplication, "What did I miss" produced 5 timestamped bullets, "Right now" answered correctly. Bugs found only by this test: (1) continuous speech never commits because finalize waited for 1.2 s of silence — meetings have none, so nothing reached SQLite; now commits at 18 words / 22 s too. (2) Stitching each pass onto the previous line duplicated sentences whenever Whisper reworded itself ("the information" vs "information"); the rolling window is now the single source of truth and only the already-emitted tail is stripped on commit. (3) gpt-oss bills reasoning against max_tokens, so catch-up answers were cut at the first heading — raise budgets (missed 1400, ask 900, now 400) and keep reasoning_effort=low (Groq rejects "minimal").
- 2026-11-15 — yt-dlp cannot fetch YouTube here (SABR/PO-token wall). Play videos in the browser and let the system-audio tap capture them; that is also the more realistic test.
- 2026-11-15 — ReCatch does NOT translate. Translation is StreamLingo's job. Answers (Right now / What did I miss / Ask) are written in the meeting's own language. The separate "answer language" picker is gone: it derives from the meeting language, and when that is Auto the prompt says "reply in the transcript's language, do not translate".
- 2026-11-15 — Auto language detection is unusable for real work meetings: on a Bahasa recording Whisper auto-detected English and hallucinated a full English transcript. Added an explicit Meeting language setting (StreamLingo has the same picker). With `indonesian` set, the transcript is real Bahasa.
- 2026-11-15 — Base vs Accurate on the user's real Indonesian meeting: Base mangled domain words ("Tim Maktat King" for Tim Marketing, "pras" for price); Large V3 Turbo got them right ("tim marketing", "di approve", "price"). For non-English meetings, Accurate is the correct default. Both answer in Bahasa.
- 2026-11-15 — The overlay is not a caption surface. Captions were removed outright, not hidden behind a toggle: ReCatch is not a translation app, the user can hear the meeting, and the Accurate tier runs on CPU with 3–6 s of lag, which makes live text worse than nothing (you read the past while hearing the present). The overlay now shows the live summary (one `.now` call every 60 s) plus an inline Ask chat, and collapses to a single summary line. A caption overlay also broadcasts your own meeting's transcript to anyone you screen-share with. Removing the caption requirement also removes the latency constraint that forced 7 s rolling windows, so ASR windows can get longer (more context = better Bahasa) at lower cost — that change is still pending.
- 2026-11-16 — Overlay is clamped, not content-sized: height = content + chrome, floor 180 pt, ceiling 430 pt, scrolling past that. Content-sized made a long catch-up stretch the panel across the screen; a fixed 430 left a void under a short summary. Also: a borderless NSPanel refuses key status by default, which is why the Ask field silently could not be typed into — `OverlayPanel.canBecomeKey = true` plus `becomesKeyOnlyIfNeeded = false` is the fix, and the shots harness now asserts `isKeyWindow` so it cannot regress.
- 2026-11-16 — The overlay is an opaque surface, not a vibrancy material, and its scrollbar is custom. A material resolved against whatever app sat behind the panel, so secondary text lost contrast over dark windows; the surface is now an explicit light/dark colour per `colorScheme`. The scrollbar follows the common design-system recipe (thin translucent overlay thumb, 4 pt at rest widening to 6 pt on hover, fades out 1.2 s after scrolling stops, hidden when content fits) because the OS scroller drew a permanent grey bar over the rounded card in a 440 pt panel.
